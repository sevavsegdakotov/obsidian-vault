# Obsidian context

For personal or project questions that may have an answer in the vault, verify Obsidian before answering and also consider relevant context already available from the conversation or product memory.

1. Search the vault for the user's terms and useful aliases. For example, a question about an apartment may require `квартира`, `хата`, `дом`, or the relevant project name.
2. Read the promising current notes rather than relying only on search snippets.
3. Compare the notes with relevant information already available in the conversation or saved memory.
4. Answer with a combined view and name the source note or notes. Clearly separate:
   - facts confirmed by Obsidian;
   - additional memory-only context that may be useful but is not yet recorded;
   - conflicts between Obsidian and memory.

Do not silently discard relevant memory merely because it is absent from Obsidian. Include it when it could materially change the answer, but label it as unverified and possibly outdated. Obsidian remains the authority for what is recorded and for the current status unless the user confirms that a newer remembered fact supersedes it. If memory and Obsidian conflict, show the conflict instead of choosing silently. Offer to save confirmed memory-only information back to Obsidian, but do not write it without the user's request.

If the Obsidian tools are unavailable, state that Obsidian could not be checked and answer from available conversation or saved memory only when useful, with the answer clearly marked as unverified. Never present remembered context as though it came from an Obsidian note.

For changes, read the target note first and prefer a focused section update or append. If the user says only “сохрани в Obsidian” without naming a destination, append a dated entry to `Входящие.md`. Never delete or move notes.
